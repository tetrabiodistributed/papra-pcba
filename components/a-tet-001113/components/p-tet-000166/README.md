## How the migration is validated (`make check`, from the repo root)

1. **Board structure** (`checks/test_board.py`): every Eagle element is a KiCad footprint with the
   same value, position, side; every pad has the same position, drill and copper size; every
   net has the same pads; the GND pour survived.
2. **Schematic** (`checks/test_schematic.py`): KiCad's own netlister reproduces Eagle's nets pad
   for pad; ERC has no errors; KiCad's schematic-parity DRC agrees board with schematic; the
   board passes the design rules translated from Eagle's `.brd`.
3. **Fab output** (`checks/test_gerbers.py`): Gerbers plotted from the KiCad board are rendered
   and XOR-compared per layer against the 2023 Eagle Gerbers; the drill files must list
   identical holes. Overlays land in `build/p-tet-000166/render/diff-<layer>.png`.
4. **3D placement** (`checks/test_models.py`): every model is placed with KiCad's own model
   transform (`checks/model_geom.py`, the matrix chain from the 3D viewer, on the geometry
   KiCad loads from the STEP file) and must sit on its side of the board with only its pins
   through it, landing on its pads. Manufacturer parts are held to datasheet numbers in
   `checks/parts.py` `PLACEMENT` (height, pin length, footprint, which way it faces).
5. **Determinism** (`checks/test_project.py`): a re-import of unchanged sources gives
   byte-identical files. kicad-cli and pcbnew mint random UUIDs and write elements in memory
   order; `checks/stable_ids.py` renames UUIDs by ordinal and sorts the board's blocks.

Known, accepted differences are listed in `checks/config.py` and `checks/project.py`.

## Regenerating

```
make import     # Eagle -> KiCad (board via kicad-cli, schematic via checks/sch_convert.py)
make check
make outputs    # ERC/DRC reports, PDFs, BOMs, Gerbers, drills, STEP, renders in build/
```

## Working in the KiCad GUI

- Open `src/papra-pcb-th/papra-pcb-th.kicad_pro`, not the `.kicad_sch` or `.kicad_pcb` on
  their own. The project carries the symbol/footprint library tables and the DRC/ERC
  severities; opened standalone, KiCad reports every library as missing and uses its
  default rules.
- Close KiCad before `make import`. KiCad keeps the project settings in memory and writes
  them back on save, which silently reverts the generated `.kicad_pro`.

## Additions over the Eagle design

- **Plated slots for the DC jack.** Eagle emulated the PJ-066A blade slots with pads, end
  holes and milling; the KiCad board has one plated oval pad per blade (`checks/parts.py`
  `SLOT_PADS`), which is what the fab produces and what DRC can reason about.
- **QR code on the bottom silkscreen** linking to https://tetrab.io, generated by
  `checks/qr.py` (content and module size in `checks/parts.py`) and placed automatically in
  the largest area free of holes, pads and other silkscreen. It is excluded from the Gerber
  comparison against the 2023 Eagle output, as are the slot pads.
- **3D models.** Standard parts use the models shipped with KiCad. The FASTON tabs, BNC,
  potentiometer and XIAO use manufacturer STEP files under `src/papra-pcb-th/3d/`
  (`3d/SOURCES.md`); their rotation and offset were solved, not eyeballed, by
  `checks/model_solve.py` from the model geometry and the datasheet rules, and are pinned in
  `checks/models.py`. The DC jack is drawn with KiCad's PJ-063AH model because Same Sky
  publishes none for the PJ-066A. To re-solve after changing a model or a rule:

  ```
  .venv/bin/python -m checks.model_solve POT1 H2 BATT+0 U1
  ```
